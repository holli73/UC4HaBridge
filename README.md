# Automic Heating for Home Assistant

Two-way sync of room heating between Automic (UC4) 24.4 and Home Assistant.
**Automic is always the source of truth**: HA only displays what it reads from Automic, and every
change made in HA is written straight to Automic and then read back.

## How it works

| Direction | Mechanism |
|---|---|
| Automic → HA | Polls `GET /ae/api/v1/{client}/objects/{vara}` for the 3 VARAs (default every 15 s). Entities update only when a value actually changed. |
| HA → Automic | Inline script via `POST /ae/api/v1/{client}/scripts`: `:PUT_VAR_COL <VARA>, "<room>", <col>, "<value>"`. No helper objects in Automic. The run is awaited (status 1900) and the VARAs are re-read right away. |
| Immediate processing | Optional **trigger object**: the same script then runs `:SET &HA_RUNID# = ACTIVATE_UC_OBJECT(<object>, WAIT)`, so Automic processes the change at once instead of at the next cycle. If the activation fails, the script stops with `:STOP MSG` and HA shows an error (the value is still written). |
| Auth | The password is entered once in the config flow and used to create an API token (90 days). Only the token is stored. Every 6 h the integration checks the expiry; 14 days before it, the current token creates its successor and the old one is deleted. If the token is rejected, HA asks you to sign in again. |

> AE 24.4 does not change any object counter or `modified_date` when `:PUT_VAR` writes, so change
> detection compares the VARA contents on each poll (3 small GETs).

### VARAs

Columns are found through the header row (key starting with `_`), so reordering columns is safe.
Rooms are the keys of the Mon-Fri settings VARA.

| VARA | Header | Used for |
|---|---|---|
| `HEATING.VARA.ROOM.INFORMATION.SUMMARY` | `_actTemp _HeatingMode _InfraHeating _FloorHeating _MustTemp` | read-only: current temp, heating state |
| `HEATING.VARA.ROOM.INFORMATION` (Mon-Fri) | `_Day _Night _Mode _TempSensor _DsSZoneID` | read/write `_Day _Night _Mode` |
| `HEATING.VARA.ROOM.INFORMATION.WEEKEND` (Sat-Sun) | same | read/write `_Day _Night _Mode` |

## Entities per room

| Entity | Maps to |
|---|---|
| `climate.uc4_<room>` | current = SUMMARY `_actTemp`; target ↔ `_Day` of **today's** VARA (Mon-Fri → weekday, Sat/Sun → weekend); off/heat + presets infra/floor/both/manual ↔ `_Mode`. Attributes: must temp, night temp, infra/floor state, active schedule. |
| `number.uc4_<room>_mon_fri_day_temperature` … (4×) | `_Day` / `_Night` of each VARA |
| `select.uc4_<room>_mon_fri_heating_mode` (2×) | `_Mode` of each VARA |

## Install

1. Copy `custom_components/automic_heating` into `<ha-config>/custom_components/` (or add this repo to HACS as a custom repository).
2. Restart HA → *Settings → Devices & services → Add integration → Automic Heating*.
3. Replace `<AutomicRestEndpoint>` with your REST URL (e.g. `http://automic-host:8088`), then enter client, user (`USER/DEPARTMENT`) and password. The VARA names are filled in by default.

## Changing settings later

Settings → Devices & services → **Automic Heating**:

| Menu | What you can change |
|---|---|
| **Configure** (gear) | Poll interval and trigger object (checked to exist; empty = no trigger). The integration reloads by itself after saving. |
| ⋮ → **Reconfigure** | REST URL, client, user, VARA names. The password is only needed if URL, client or user change; a new API token is then created. If you leave it empty, the current token is kept. |
| ⋮ → **Re-authenticate** | Shown automatically if the token is rejected. |

Requires Home Assistant 2025.8 or newer.

## Logo

Icons and logos are in `custom_components/automic_heating/brand/` and are generated by
`tools/make_brand.py`. Home Assistant shows them from **2026.3** on; older versions work but show no logo.
A browser cache refresh may be needed after updating.

## Development

```sh
python3 -m venv .venv && .venv/bin/pip install uv
# override pins lru-dict to a prebuilt wheel (1.3.0 does not compile with older Xcode clang)
echo "lru-dict==1.4.1" > /tmp/overrides.txt
.venv/bin/uv pip install --python .venv/bin/python --override /tmp/overrides.txt pytest-homeassistant-custom-component
AE_URL=http://<host>:<port> AE_PASSWORD=... .venv/bin/python tools/live_test.py   # live API test, touches only ClaudeRoomTest
.venv/bin/pytest tests                               # HA tests, Automic mocked
```
